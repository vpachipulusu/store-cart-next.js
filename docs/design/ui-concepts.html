From boilerplate to a merchant's workspace

These four screens keep the ivory, navy and champagne-gold identity already in the app and change what it is built around: the merchant's store, orders and plan. They are layout concepts drawn as HTML, not Figma files, and they have not yet been checked against the running app.

What the code review found

Landing is still the templateHero says "Next.js 16 + React 19", links to a placeholder GitHub repo, and sells a boilerplate, not StoreCart.
White text on gold14 buttons pair bg-theme-accent with text-white. Gold with white is about 2.1:1; navy on gold is about 8:1.
Headings fall back to Georgiafont-display points at --font-display, which nothing defines. The serif is an accident, not a choice.
Account pages, not store pagesDashboard is a top bar with five links and a stack of identical cards about the user's account.

Display: Fraunces, used for headings and big numbers only. Body: Hanken Grotesk. Data and labels: IBM Plex Mono with tabular numerals. Gold is the one accent; success, warning and critical are separate semantic colours.

Proposed plan

  1. Foundation: define --font-display, fix accent button contrast (navy on gold), add status colours, keep both themes. About 14 button usages plus tokens.
  2. Shell: replace the dashboard top bar with a sidebar layout shared by the dashboard and admin.
  3. Landing and pricing: replace template copy with StoreCart copy; recommended-plan treatment.
  4. Auth screens: split layout, inline errors, and the 2FA step when KAN-125 lands.
  5. Verification: screenshots at 375, 768 and 1440 in both themes, keyboard and contrast checks, then Playwright visual baselines once E2E is on.

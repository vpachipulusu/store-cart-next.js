# Platform models and the Alembic baseline (KAN-36)

SQLAlchemy models for the platform database (ADR-005, ADR-010) are in `fastapi_backend/app/models/platform/`, one
aggregate per file, registered in the package `__init__.py`. Revision `0001` (`0001_platform_baseline.py`) creates
them. Store data (products, orders, customers) and Stripe Connect are out of scope.

## Conventions

- Own `MetaData` with a naming convention (`pk_`, `uq_`, `ix_`, `fk_`, `ck_`); composite indexes are named explicitly.
- Typed `Mapped[...]`, snake_case table and column names, plural table names kept from Prisma (`@@map`).
- Primary keys are text, generated by `app.core.ids.new_id` (cuid2, `cuid2==2.0.1`). Prisma ids (cuid) are plain strings
  and copy across unchanged.
- Timestamps are `timestamptz` with `now()` server defaults; `updated_at` also uses `onupdate=now()`.
- Enums (membership role, invitation status, store status) are short text plus a named CHECK, not native Postgres enums,
  so adding a value is a one-line migration.

## New tables

| Table | Notes |
|---|---|
| `organizations` | `stripe_*`, `subscription_tier` (default `free`), `subscription_status` (default `inactive`), `platform_fee_bps` (default 0). |
| `memberships` | Role `OWNER`, `ADMIN` or `STAFF`; unique `(organization_id, user_id)`; cascades from both parents. |
| `invitations` | Stores a hash of the token, never the token. Status `PENDING`, `ACCEPTED`, `REVOKED`, `EXPIRED`. |
| `stores` | Registry: organisation, unique `slug`, status, `schema_version` (migrations applied), nullable `database_ref`. The reference locates the store database and is never a connection string or credential. |

## Subscription plan catalogue (KAN-42)

`app/core/plans.py` holds the static plan catalogue (`PLANS`, `get_plan`, `is_within_limit`); it is keyed by the same
values as `organizations.subscription_tier` (`free`, `pro`, `enterprise`). Each plan sets `max_stores`, `max_products`
and `max_staff` (`None` is unlimited) and `platform_fee_bps = 0`. The limit values are configurable defaults, not
product decisions. It has no Stripe calls or tables: billing endpoints and the webhook are KAN-43 and KAN-44.

## Intentional differences from `prisma/schema.prisma`

- Subscription fields moved from `users` to `organizations` (ADR-010). `users` keeps no billing columns.
- `audit_logs` gains nullable `organization_id`, indexed `(organization_id, created_at)`. It has no foreign keys (as in
  Prisma), so the trail outlives users and organisations.
- Timestamps are `timestamptz`; Prisma used `timestamp(3)` without a zone. Copy data with the source zone known (UTC).
- Prisma strings and `@db.Text` are all `text`; `Json` is `jsonb`.
- Redundant indexes were dropped where a unique constraint already indexes the column: `users(email)`,
  `users(firebase_uid)`, `seo_meta(page)`, `email_templates(name)`.
- `audit_logs.metadata` is the `metadata` column, exposed as `AuditLog.metadata_` (the name `metadata` is reserved on declarative classes).
- Defaults are server-side where Prisma had a database default (`now()`, booleans, strings, integers). The id default and
  `updated_at` refresh are applied by SQLAlchemy, as Prisma applied them in its client.

## Migrating

`DATABASE_URL_DIRECT` (Neon unpooled) is used by Alembic when set, else `DATABASE_URL`. `sslmode` in the URL is passed to
asyncpg as `ssl`; other query parameters are dropped. Run `alembic upgrade head` only on a database you own. CI runs
`upgrade head`, `alembic check` and `downgrade base` on a Postgres 17 service container.

**Deploying a backend PR that adds a platform migration (KAN-253).** No build or deploy runs migrations (ADR-011).
Before or right after the deploy, run `uv run alembic upgrade head` from `fastapi_backend/` against the production
platform database (`DATABASE_URL_DIRECT`). Until then every query on the changed tables fails, and `GET /health/ready`
(header `X-Internal-Key`) answers 503 `migrations_pending` with `migrations.current` and `migrations.head`. The PR that
adds the migration also appends its revision id to `PLATFORM_REVISIONS` in `app/core/platform_schema.py`;
`tests/core/test_platform_schema.py` fails until it does.
